# PSP-UFU 中文界面完善指南（路径与操作步骤）

> 现状数据来自对 `Project/data/lang/zh_CN/zh_CN.po` 与 `pt_BR/pt_BR.po` 的静态解析。

### 1.4 关键机制事实（决定后续步骤）
1. **运行时加载的是 `.mo`，不是 `.po`**。`main.cpp` 通过 `wxLocale::AddCatalog("zh_CN")` 加载 `data/lang/zh_CN/zh_CN.mo`。**只改 `.po` 不重编译 `.mo` 界面不会变。**
2. **仓库无自动编译脚本**：`.vcxproj` 仅把 `.mo`/`.po` 当作 `<None>` 项（`Project/data/lang/zh_CN/zh_CN.mo`），没有 post-build 自动编译/拷贝。编译需手动（Poedit 或 `msgfmt`）。
3. **本机当前没有 `msgfmt`**（gettext 未安装），需先装工具。
4. `.po` 由 **Poedit** 生成（含 `#: 源文件:行号` 引用），翻译时可点击跳转源码看上下文。
5. `.po` 的 `POT-Creation-Date` 为 **2024-06-19**，可能落后于当前源码——翻译前应先**从源码重新提取**新字符串（`msgmerge`/Poedit "更新来自代码"），否则新增 UI 文本不会被纳入。

## 2. 完善路径（两条路线，任选）

### 路线 A：Poedit（推荐，零命令行）
适合大多数开发者/翻译协作。Poedit 是图形化 `.po` 编辑器，**保存时自动生成 `.mo`**，并显示源码上下文、曾译记忆、拼写检查。
- 安装 Poedit（免费版即可；专业版支持"从代码更新"与机器翻译预填）。
- 直接打开 `Project/data/lang/zh_CN/zh_CN.po`，逐条填 `msgstr`，`Ctrl+S` 即生成同目录 `.mo`。

### 路线 B：gettext 命令行（适合 CI / 批量 / 自动化）
- 安装 gettext（含 `msgmerge`、`msgfmt`）。
- 流程：`msgmerge` 更新 `.po` → 编辑 → `msgfmt -o zh_CN.mo zh_CN.po` 编译 → 部署 `.mo`。

> 建议：**路线 A 起步最快**；若要把"汉化"纳入你们教学工具的持续构建，再用路线 B 写成脚本。

## 3. 操作步骤（可执行的 7 步）

### Step 1 — 准备工具
- 路线 A：安装 [Poedit](https://poedit.net/)，打开项目 `.po` 即可。
- 路线 B：安装 gettext（`msgfmt`/`msgmerge`）。Windows 可用 [gettext for Windows](https://mlocati.github.io/gettext-iconv-windows/) 或 `choco install gettext`；Linux `apt install gettext`。

### Step 2 — 从源码更新字符串（重要，先做一次）
确保覆盖 2024-06 之后新增的 UI 文本：
- Poedit：菜单 `Catalogue → Update from source`（需 `.po` 里已配置的 `X-Poedit-SearchPath-0: .` 指向 `Project/`）。
- 命令行：
  ```bash
  # 先生成最新模板 pot（若没有），再合并
  xgettext -k_ -o messages.pot -D Project --from-code=UTF-8 $(find Project -name '*.cpp' -o -name '*.h')
  msgmerge -U Project/data/lang/zh_CN/zh_CN.po messages.pot
  ```
  合并后会出现新条目（未译）和废弃条目，照常处理。

### Step 3 — 翻译 `.po`
- 对照葡语 `pt_BR.po` 看完整译文风格（术语一致）。
- **务必保留原文的格式符**，否则运行时崩溃或显示异常：
  - 快捷键：`&Bus` → 中文可写 `母线(&B)`，但 `&` 与 `\t` 必须保留；
  - 制表/分隔：`\t`（如 `"&Bus\tB"`）；
  - 占位符：`%d`、`%s`、`%.2f` 等原样保留；
  - 不要删掉行尾换行或引号转义。
- 中文无需复数（`.po` 已设 `nplurals=1; plural=0;`，正确）。

示例（翻译前后）：
```po
# 翻译前
#: forms/TransformerForm.cpp:30
msgid "Rated power"
msgstr ""

# 翻译后
#: forms/TransformerForm.cpp:30
msgid "Rated power"
msgstr "额定功率"
```

### Step 4 — 编译为 `.mo`
- Poedit：`Ctrl+S` 自动在同目录生成 `zh_CN.mo`。
- 命令行：
  ```bash
  msgfmt -o Project/data/lang/zh_CN/zh_CN.mo Project/data/lang/zh_CN/zh_CN.po
  ```

### Step 5 — 部署 `.mo` 到运行位置
`main.cpp` 在运行时从**可执行文件所在目录的上一级**查找：
```
<exe_dir>/../data/lang/zh_CN/zh_CN.mo
```
- 确认调试/发布时 `Project/data/lang/zh_CN.mo` 被复制到该路径（VS 默认 `<OutDir>` 为 `x64/Release/`，需保证 `../data/lang` 可达；可加 post-build 拷贝 `Project/data → $(OutDir)..\data`，或在 VS 项目"调试→工作目录"指向含 `data/` 的父目录）。
- 直接把编译好的 `.mo` 放回 `Project/data/lang/zh_CN/`（已纳入仓库 `<None>` 项），随工程分发。

### Step 6 — 验证
1. 启动 PSP-UFU → 设置（`Settings`）→ 语言选 `中文(简体)`（或改 `config.ini` 的 `lang=zh-cn`）→ 重启。
2. 走一遍主流程：新建工程 → 加母线/线路/发电机 → 双击改参数（应全中文）→ 跑潮流/短路/稳定 → 看报表/曲线/仿真提示（应全中文）。
3. 对照上面"最大缺口表"逐文件核对，标记遗漏。

### Step 7 —（进阶）处理未包裹 `_()` 的硬编码文本
少数界面文本若没用 `_(...)` 包裹，即使 `.po` 译了也不会生效。遇到"怎么译都不显示中文"的字符串：
- 在源码里用 `_("...")` 包裹该字面量；
- 重新执行 Step 2（提取）→ Step 3 → Step 4。
- 建议顺手把这类硬编码统一改造，纳入代码规范。

## 5. 注意事项（避坑）

- ⚠️ **只改 `.po` 不重编 `.mo` = 白改**：每次翻译后必须 `msgfmt`/Poedit 保存生成 `.mo`。
- ⚠️ **格式符必须原样保留**：`&`、`\t`、`%d`、`%s` 错位会导致 UI 异常甚至崩溃。
- ⚠️ **编码 UTF-8**：`.po`/`.mo` 均为 UTF-8，编辑器勿转 GBK。
- ⚠️ **与上游同步**：若你们持续跟踪 PSP 上游，定期 `msgmerge` 把上游新串合并进来，避免长期分叉后大规模冲突。
- ✅ 利用 `#: 源文件:行号` 引用：翻译不确定时，在 Poedit 点引用跳到源码看上下文（如表单标签、单位、提示语）。
- ✅ 复用 `pt_BR.po` 作为术语与句式参考，保证一致性。

## 6. 给"教学工具"的额外建议
1. **汉化应作为第一里程碑**：界面语言是教学工具可用性的门槛，优先级高于花哨功能。
2. **众包可行**：`.po` 天然适合分文件、分模块分配给多名助教/学生并行翻译（结合上面的"最大缺口表"切任务）。
3. **补中文手册**：`docusaurus/` 已有中文文档骨架，可同步把用户手册汉化，形成"软件+文档"完整中文教学包。
4. **纳入构建**：等汉化稳定后，把 `msgmerge` + `msgfmt` 写成一个 `update-translations.bat/.sh`，挂到你们的 CI/构建前步骤，避免后续漂移。
